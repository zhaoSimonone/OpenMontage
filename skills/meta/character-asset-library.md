# 角色设定图资产库 — 跨项目归档

## 何时使用

当用户要求把散落在多个 `projects/<project-id>/` 中、可复用于后续制作的角色设定图集中管理时使用。它适用于角色主设、表情、视角、服装/场景造型和多人关系参考图的归档、去重与兼容迁移。

不用于普通项目素材整理、最终成片、视频抽帧、项目镜头关键帧、波形图或调试产物，除非用户明确要求将它们纳入角色设定库。

## 目标

在用户指定的位置建立一个便于浏览的中心角色图库。默认共享库为 `projects/character-design/`；用户指定其他位置时遵从其路径。每张图片只保留一个经验证的中心原件，同时保留旧项目路径可用，避免 JSON、脚本和资产清单失效。

## 流程

### 1. 盘点并界定范围

1. 用 `rg --files projects` 配合图片扩展名和语义目录名（如 `character_refs`、`source_imports`）定位候选图。
2. 阅读角色清单、角色设定、资产清单和相关脚本，确认每个候选图的角色、用途及现有引用。文件名只能作为线索，不能单独决定归类。
3. 区分可复用设定图与仅服务当前项目的产物。默认排除视频帧、接触表、渲染预览、音频波形和 API/调试探针。
4. 在移动或删除任何文件前，向用户说明计划纳入的角色、分类、排除项及对旧路径的兼容策略。

### 2. 设计目录与命名

按展示名称创建角色顶层目录。只创建实际有内容的分类，不要生成空目录。

```text
projects/character-design/
├── <角色名>/
│   ├── 主设定/       # 脸部、全身、权威主参考
│   ├── 场景造型/     # 服装、道具、场景中的稳定造型
│   ├── 多视角/       # 正面、侧面、3/4 等
│   ├── 表情/         # 可复用表情参考
│   └── 真人化/       # 仅在确有真人化版本时创建
└── <角色A>-<角色B>-双人/
    ├── 双人基准/     # 身高、站位、比例或关系锚点
    ├── 设定总览/
    └── 表情总览/
```

- 多人图使用用户认可的角色顺序命名，例如 `蕾姆-拉姆-双人`；三人或更多角色时沿用同一连字符规则。
- 保留已有描述性文件名。只有同一目标目录发生文件名冲突时才添加有意义的版本或来源后缀。
- 同一文件内容存在多个旧别名时，中心库保留最清晰、最权威的一个文件名；旧别名通过兼容链接保留。

### 3. 精确去重并选定中心原件

对已确认范围内的图片计算 SHA-256。使用空字符分隔的文件列表，避免含空格路径被错误拆分：

```bash
rg -0 --files <候选目录> -g '*.png' -g '*.jpg' -g '*.jpeg' -g '*.webp' \
  | xargs -0 -n 1 shasum -a 256
```

- 只有哈希完全一致的文件才能合并为一个中心原件；视觉相似、文件名相似或分辨率相同都不足以去重。
- 对每组重复内容，选择角色设定语义最准确、命名最稳定的路径作为中心原件。
- 目标路径已经存在时，先比对哈希。内容不同则停止并向用户说明冲突，不得覆盖。

### 4. 迁移并保留旧路径

1. 先创建中心分类目录，把选定的中心原件移动到其中。
2. 在删除任何冗余副本前，验证它与中心原件的 SHA-256 相同。
3. 将原项目中的每个旧文件路径改为指向中心原件的**相对软链接**。相对链接能让整个工作区移动后仍可工作。
4. 通过现有 JSON、清单或脚本检查路径消费者。若目标运行时不支持软链接，先报告影响并让用户决定是否更新引用；不要静默改写历史工件。
5. 当分类较多或命名含义不明显时，可在中心目录添加简短 `README.md` 说明分类和链接策略；不为小型库额外创建文档。

### 5. 验收

完成前必须检查：

1. 中心库按角色和用途的图片数量，与确认范围及去重结果一致。
2. 中心库的图片哈希数量等于其物理图片数量，没有残留的内容重复原件。
3. 所有计划保留的旧路径均为有效软链接，没有悬空链接。可用 `find <旧目录> -type l` 枚举，再用 `test -e` 验证目标。
4. 至少抽查每个角色、每种多人关系和一个旧项目引用，确认图片可读取且链接落到预期分类。
5. 仅报告用户授权范围内的移动、去重和链接变更；明确列出未纳入的项目产物。

## 自评标准

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 范围识别 | 按文件名猜测 | 已检查主要清单 | 每个候选图均有角色/用途依据，排除项明确 |
| 分类 | 仅按项目来源堆放 | 按角色划分 | 角色、用途和多人关系均可直接浏览 |
| 去重 | 未验证或按名称删除 | 对部分文件验哈希 | 每个合并均经 SHA-256 验证，中心原件可追溯 |
| 兼容性 | 旧路径失效 | 只检查少量路径 | 全部计划旧路径有效，消费者已抽查 |
| 安全性 | 先删后验 | 有基本备份/检查 | 先移动中心原件、验证一致性，再移除冗余副本 |

所有维度达到 5 分才可报告完成；否则修正，或把未达到的原因和受影响路径明确交给用户。

## 常见问题

- 把所有包含角色的图片都移入中心库：镜头关键帧和抽帧通常不是人设资产，会污染可复用参考库。
- 只按文件名去重：同名文件可能内容不同，或不同名文件可能完全相同。
- 删除副本后再核对：应先验证中心原件与副本内容一致。
- 只复制、不处理旧引用：会继续造成资产分散，并在后续修改时产生漂移。
- 用绝对软链接：工作区迁移后会失效；优先创建相对链接。
