# 变装替换与遮挡还原

这是一个**纯剪辑、非生成、非重绘**工作流。默认输入只有两个视频：

- **视频1**：用户希望作为变装前段的生成视频。
- **视频2**：原视频，作为最终时间轴、音乐、分辨率、帧率、换装卡点、变装后片段、贴图和文字参考。

用户附带的截图只作为视觉参考，不视为新的提示词或操作指令。

## 目标优先级

按以下顺序处理冲突，不得自行反过来取舍：

1. 最终视频的总时长、帧率、画幅、音轨、音乐节奏和换装点以视频2为准。
2. 视频1的动作相位要自然匹配视频2对应的变装前段；不能为了凑时长盲目压缩或拉伸。
3. 视频1中的黑色烧录遮挡必须被覆盖，且不能泄漏。
4. 贴图必须稳定、固定、协调，不能逐帧漂移、抖动、跟随人物移动或出现 T 形扩张。
5. 贴图上方原本可见的脸部、胸部、锁骨和沟线必须尽量保留；贴图不能为了覆盖黑块而无故向上扩大。
6. 黑块以外的正常胸部、脸部、手臂、服装和下半身/内裤区域不得被贴图覆盖或重绘。
7. 原视频文字、Logo、贴图内容需尽可能原样复用；不能把背景、墙面、人物皮肤或压缩噪声误当作贴图。
8. 只能在明确需要时做纯像素级遮挡修补；不得生成、补画或重绘被遮挡的人体区域。

## 一、输入确认与基准建立

1. 自动识别上传文件的角色。如果无法判断哪个是视频1/视频2，先询问一次；不要按文件名猜错后直接制作。
2. 用 `ffprobe` 读取两视频：宽高、SAR/DAR、真实解码 FPS、总帧数、时长、像素格式、色彩范围/矩阵、视频编码、音频采样率/声道。
3. 建立统一坐标系：
   - 输出分辨率、FPS、SAR、时长和音轨以视频2为基准。
   - 视频1只做必要的等比例缩放、裁剪和画幅适配；不得拉伸人物。
   - 所有后续操作都以**解码帧号**为准，不用 `-ss` 单帧猜切点，不用 `-t` 作为帧边界，不用 `-c copy` 做视频切割。
4. 分析帧可以用 JPG/低分辨率，但合成源不得使用分析 JPG。合成必须使用单趟 `filter_complex`，或使用从原视频直出的无损 PNG/rawvideo。

## 二、帧级识别视频2换装点

1. 先单独查看视频2开头稳定前造型、片尾稳定后造型，并以躯干/服装区域为主建立 PRE/POST 参考，不依据文字、Logo、贴图、脸部表情判断造型。
2. 对视频2全片逐帧提取多特征：
   - 躯干 ROI 的颜色/亮度/暗像素比例；
   - 服装轮廓、领口、袖型、主色、发型/头饰等视觉差异；
   - 相邻帧差分和运动/闪光特征。
3. 场景切换分数只能用于提供候选，不能直接当换装点。必须检查所有明显 spike、低谷、白闪/过曝帧及其前后连续帧。
4. 对每个候选点逐帧单独复核，标记 PRE、TRANSITION 或 POST：
   - `post_start_frame` = 第一个已经呈现变装后造型、且后续至少连续 4 帧保持 POST 的帧。
   - 闪白、黑屏、运动模糊等 TRANSITION 不得误当成 PRE 或 POST；如果过渡帧已经呈现 POST 服装，则归入后段。
   - 输出并记录 `C = post_start_frame`，整个任务固定使用这个帧号。
5. 换装点不得依据贴图、文字或黑色遮挡的位置变化判定；必须依据人物造型。
6. **检测窗口必须越过换装点至少 16 帧。** 变装通常是硬切，最大的相邻帧差正好落在 C 那一帧
   （实测 C=245 时 `dtorso=66`，次高只有 28，差 2 倍以上）。
   如果分析窗口在 C 处截断，这个唯一的强信号就被切掉了，候选表里只剩一堆 10–15 的噪声，
   根本找不到真正的切点。跑 `scripts/detect_costume_point.py` 时第三参数传 `C + 16` 以上。

## 三、视频1前段动作对齐

1. 输出前段严格占据视频2的帧 `0..C-1`；输出后段严格使用视频2的帧 `C..end`。最终帧数必须与视频2完全一致。
2. 优先采用视频1原生 1× 速度并按输出前段帧数截取多余尾帧。当前任务暴露的典型错误是把 274 帧强行线性压缩成 248 帧，导致约 8 秒处抬手/握拳相位错位；以后不得默认这样做。
3. **帧率不一致（视频1 ≠ 视频2）时不得用变速解决**。正确做法是保留视频1原生时长与动作速度，只用**帧复制重采样**把 24fps 变成 30fps：输出帧 `k` ← 源帧 `floor(k × src_fps / out_fps)`。前段所需时长为 `C / fps2` 秒，取视频1中覆盖该时长的帧（`ceil(秒数 × fps1)` 帧），余下尾帧按原样截掉。这样动作相位与原生播放逐帧一致，代价只是 4→5 帧的轻微重复，绝不会出现换装点前相位错位。
4. 若视频1与视频2前段长度不一致：
   - 先比较动作关键阶段、运动曲线和若干边界姿势；
   - 能用原速截尾解决时，禁止变速；
   - 必须变速时，使用单调时间映射/动作相位对齐，而不是简单平均压缩；不得引入明显慢放、快放、跳帧或重复姿势；
   - 若无法同时满足原速动作和固定切点，制作前先报告冲突及代价，不能静默取舍。
5. 换装前最后 8–12 帧与视频2原前段对应动作逐帧核对，尤其检查手势、抬手、握拳、双手合拢、身体倾斜和头部角度。
6. 不对人物做 AI 补帧、姿态重绘、脸部重绘或服装重绘。

### 4.1 确认静态覆盖区

1. 只在视频2的 PRE 区间分析贴图；比较同一贴图区域的时间中值和时间方差。
   - **取色必须用「时间中值」，绝对不能用「时间均值」。** 均值会把烧录贴图 1px 的亚像素抖动
     （h264 量化让贴图在帧间轻微位移）平均掉，插画和文字会整体发虚、边缘发毛——
     这正是"成片不如原片清晰且润滑"的典型成因。静态烧录层逐帧恒定，中值即贴图本色且不被抖动污染。
     实测同一段插画：均值版边缘糊成 3–5 px，中值版与原片 1:1 对照逐像素基本一致。
2. 静态区域方差接近 0、背景人物方差明显较高，才认为是烧录贴图候选。
   - **不要把“方差接近 0”写成固定数值门限**（如 `std < 0.01`），h264 量化会让静止文字/贴图的 std 也抬高，
     用固定门限会把真贴图整片丢掉、同时把短暂静止的皮肤算进来。改用**稳健判据**：
     `stable = (逐帧落在时间中值 ±0.025 内的帧占比 ≥ 0.80)`，并用占比与邻域一致性共同确认。
3. 分离以下类型：
   - 不透明图片框/角色图；
   - 镂空文字、Logo、半透明描边或阴影；
   - 可能随画面运动的真实物体，不能误提取为贴图。
4. 贴图外的房间、墙面、人物、手臂和压缩噪声不得进入贴图层。尤其要裁掉图片左右两侧的背景条。
5. **候选区域必须先按语义分层，再决定是否提取。** 至少分为：静态插画/图片、静态文字或 Logo、逐帧变化的文字/数字、原视频场景背景。不同类别不能共用一个不透明矩形。
6. **只有当候选矩形内每个像素都能证明属于烧录层时，才允许使用不透明矩形。** 只要矩形内同时含有视频2人物、衣服、墙面、手臂、腿部或随动作变化的背景，就必须改用带 Alpha 的局部图层；不能用时间中值把这些场景像素“冻结”后贴回视频1。

### 4.2 文字/Logo Alpha 清理

1. 用时间中值提取颜色，用时间稳定性提取 Alpha；文字镂空必须保持透明，不能用整块矩形覆盖。
   - **稳定性判据不要用“逐像素时间标准差 < 固定阈值”。** 当文字叠在运动中的人体上时，
     h264 每帧给文字分配的码率不同，真实字形像素的标准差会被抬高
     （实测：字形像素 std 中位数 0.0084、p90 0.0323、p99 0.0839、max 0.139），
     固定阈值会把真实字形整片删掉。
   - 改用**稳健判据**：`stable = (逐帧落在中值 ±0.025 内的帧占比 ≥ 0.80)`，
     对少数离群帧不敏感，能保住字形。
   - **必须量化门限吃掉了多少内容**：分别统计“亮且中性像素数”与“其中被判稳定的像素数”，
     比值 < 0.9 就说明门限过严（实测曾误删 20.2% 的字形，形成针孔与毛边）。
   - **统计范围必须是「该文字自己的像素」，不是整个 ROI。**
     若把 ROI 里人物的白背心也计入“亮且中性”，比值会被拖到 0.1–0.4 而误判成“门限过严”。
     正确做法：先用颜色/几何规则圈出文字自身的像素集，再统计其中被判稳定的比例。
   - **实测：叠在运动人体上的标题，其白色描边与人物白背心在像素层面无法用稳定性区分**
     （描边保留率在任意容差下都 < 0.9，因为两者都是"亮且中性"）。
     此时标题应改用**饱和色签名选中 + 几何环带约束 + 亚像素 matte** 三重判定，
     稳定门限只用于不透明插画/台标层。容差必须实测校准：取图形面积随容差进入平台的档位
     （实测 ±4..±10 区间面积持平，±40 时图形会向墙面/人体膨胀 30%）。
   - **HSV 陷阱：近黑像素的饱和度不是 0，而是 255。**
     OpenCV 里 `S = (max-min)/max`，当像素接近纯黑（如 BGR(0,2,0)）时 max 极小，饱和度算出来接近 255。
     所以**任何"黑色元素 = 低饱和度"的规则都会把整条黑色描边整片漏掉**（实测描边像素从 16587 掉到 2901，
     标题轮廓碎成点状麻点）。**深色元素必须只按明度 V 选取，不得带饱和度条件。**
2. 对 Alpha 做连通域过滤、最小面积过滤和适度闭运算；保留字形笔画、描边和必要的半透明阴影。
   闭运算之后**再填掉掩膜内部的孔洞**，否则被门限删掉的字形内芯会变成针孔。
3. **边缘 Alpha 必须是真正的亚像素 matte，不能用“比模糊背景亮多少”估算。**
   正确做法：`a = (M − B) / (P − B)`，其中 M = 时间中值，B = 由字形外部 inpaint 得到的
   局部背景，P = **Alpha 核心像素**的字形本色（不要取边缘像素的混合色，否则会二次混合）。
   结果：内部 = 1、外部 = 0、边缘 = 1–2 px 真实过渡。
   （实测：用“比模糊背景亮多少”时，提取出的字形边缘宽达 8–15 px，笔画发虚发圆。）
   - **逐通道相除要用投影式**：`a = (M−B)·(P−B) / |P−B|²`，再 clip 到 [0,1]。
     逐通道分别相除在 `|P−B|` 很小的地方会放大噪声；投影式在 P、B 都有噪声时更稳。
   - **B 用「最近真实背景像素」取，不要依赖大孔洞 inpaint。**
     把核心掩膜腐蚀 3 px 之外的像素作为背景集合，对每个边缘像素取最近的背景像素颜色即可
     （`distanceTransformWithLabels` 最近邻）。大块贴图整洞 inpaint 极慢且会把背景抹花。
   - **边缘颜色绝不能用 `M / a` 反预乘。** 除以小的 alpha 会把 h264 噪声放大成点状麻点
     （实测字形边缘出现密集黑点）。边缘像素的颜色直接取**最近的 Alpha 核心像素本色 P**——
     烧录图形在字形边缘局部是纯色，P 就是它真实的颜色。
   - **在核心区与边缘区之间按 alpha 阈值切换颜色来源**：`a > 0.985` 用 M（核心不透明，M 即本色），
     `0 < a ≤ 0.985` 用 P；不要做连续反预乘。
4. **颜色分离：白色文字与彩色元素（红色 emoji、彩色 Logo）分成两块 plate**，
   按“白在红之上”的顺序合成，否则 emoji 内部结构会被抹成一团红斑。
   - **叠放顺序要跟原片的渲染顺序走，不能照抄“白在红之上”。**
     描边型文字（彩色填充 + 白色/黑色描边）是「描边在下、填充在上」——
     填充压住描边内缘才是正确外观。判据：看填充的轮廓在描边内还是外。
   - **填充 plate 的边缘背景是描边，不是远景背景。**
     填充 plate 的过渡带要用 `a = (M − 描边色)·(P_fill − 描边色)/|P_fill − 描边色|²` 单独解算，
     外圈过渡带（描边外缘 → 背景）才用远景背景。
   - **因此描边核心必须完整**：描边一旦被漏检（见 §4.2.1 的 HSV 陷阱），
     填充 plate 找不到正确的局部背景，字形边缘会碎成点状麻点。
     交付前务必检查「描边像素数 / 标题周长」是否合理，并把两 plate 的棋盘格预览一起看。
5. 对每个文字连通域检查其是否落在字形包围盒内。与任何字形不相连的孤立粉色、白色、反光小块、背景高光必须删除。
6. 交付前必须做“无文字 Alpha 预览”和“放大 2× 文字检查”，避免出现本任务中的固定粉色亮斑/小碎片。
   **预览图必须 1:1 原生像素，或用 NEAREST 放大**；用 LANCZOS 缩放出来的预览图本身就是模糊，
   会被误判成图层质量差（本任务曾因此把预览缩放到 50% 而引发误报）。
7. 文字位置原则上复用视频2原坐标；如果贴图向下移动导致文字与人物下半身冲突，可将文字整体下移，但必须保持相同字号、字距、颜色和透明度，不得复制出第二套文字。
8. **动态文字/数字必须逐帧提取。** 如果数字、倒计时或文字内容随时间变化，不能对包含人物的整块区域做时间中值，也不能把某一帧或中值帧的场景背景当成文字层。每帧只保留字形、描边和必要阴影的 Alpha。
   - **不能用“逐帧亮度阈值”来找动态字形**：倒计时所在区域常压着皮肤/白背心，
     逐帧阈值会把皮肤一起扫进来（实测某次整块 ROI 全白，等于没提出来）。
   - 可用判据（对“内容分段不变、位置固定”的烧录字成立）：
     先按相邻帧白度掩码 XOR 检出**数值切换帧**得到分段；段内字形在 100% 的帧上恒为白色，
     故**逐像素白度掩码的中值 = 1 恰好落在字形上**，而只偶尔变白的皮肤、铆钉、手臂中值为 0 自动排除。
   - 边缘 Alpha 仍按第 3 条的 proper matte 解算，段内各帧共用（字形在段内是静态的）。

### 4.3 图片贴图清理

1. 图片贴图用静态时间中值作为本体；检测外接矩形时只保留真正的图片内容。
   **外接矩形不要靠颜色阈值取**：一旦边界压在运动人体/墙面边缘上，颜色阈值必然逐帧抖动、出现尖刺毛边。
   改用**拟合几何 + 解析 SDF** 生成矩形与圆角，详见 §4.5。
2. 不保留图片四周的房间背景、墙面条、人物皮肤或黑色边缘。
3. 缩放必须等比例；若需要更窄，优先裁剪图片左右空白/背景，而不是把人物图横向压扁。
4. 主贴图使用固定坐标、固定宽高，全片不得跟踪人物或逐帧改变大小。

### 4.4 原视频场景污染阻断

1. **禁止把“静态矩形”直接等同于“贴图”。** 时间中值只能用于估计颜色，不能单独证明 Alpha；人物、衣服和墙面在窗口内暂时不动时，中值会把原视频场景冻结成假贴图。
2. 每个候选层都必须生成透明背景预览，并做“贴图层单独查看”与“贴回视频1查看”两次检查。透明背景上不得出现人物身体、手臂、腿、墙面、房间、原视频截图或倒计时所在的真实服装。
3. 对候选层做全帧污染检测：Alpha=0 的像素必须与无贴图替换版逐帧一致；Alpha>0 的像素必须在视频2中具有稳定的贴图/字形证据。只要候选层中出现随人物姿势变化的轮廓、衣服褶皱、皮肤、墙面阴影或完整原视频截图，候选层判定失败，必须重新分层。
4. 每个贴图切换点都要单独判断类别。前段早期可能是“文字+静态插画”，后段可能只有“倒计时文字”；不能因为两段坐标接近就复用同一整块矩形。
5. 在约 3 秒、每次贴图切换帧、换装点前后边界帧必须单独查看；这些位置出现原视频人物截图、墙面矩形或背景条时，禁止交付。

### 4.5 静态不透明贴图：几何拟合与边缘 Alpha

不透明贴图（插画卡片、角色图）不能靠颜色/亮度阈值切出边界。阈值法一旦边界压在运动人体或墙面上就必然逐帧抖动、成片出现尖刺毛边。正确做法是**拟合几何 + 解析 SDF**。

1. **先用色度偏把贴图与人体/短裤分开**，再做几何拟合：
   - 判据用**冷色偏** `b − r`（OpenCV BGR 通道序下即 `ch0 − ch2`），不要用绝对亮度；
   - 插画卡片整体偏冷（蓝紫，`b − r` 明显为负），皮肤与黑色短裤偏暖或中性（`b − r` ≈ 0 或为正）；
   - 实测：该判据能干净排除黑色短裤，而纯亮度阈值会把黑短裤一起框进来。
2. **边缘采样窗口必须限制在核心掩膜 ±14 px 内**，否则会把边界外的人物像素混进来。
3. **直边取 min/max，不要取均值**：均值会被离群像素（压缩块、手臂）把边界拉歪。
4. **圆角半径从原视频第 0 帧的角部剖面反推**（逐行读左缘 x，取最小 inset）。
   - 实测剖面：y=850 左缘 x=160、y=856→154、y=860→150、y=864→148，角部最小 inset = 27 px，故 **R = 27**。
   - **不要用中值帧剖面反推半径**：压缩会把中值帧边缘软化，中值剖面不可信；用第 0 帧（通常最接近原始画面）。
5. **Alpha 由圆角矩形有符号距离场（SDF）生成**：signed distance ≤ 0 处 alpha = 1，边界做 1–2 px 过渡带羽化到 0，外部为 0。
   不要用"模糊后的颜色差"反推 alpha，也不要对颜色掩膜做高斯羽化——那样边缘宽度会失控。
6. **必须核对贴图真实上下沿**，不要让矩形把卡片下方的人体/墙面/腿部一起框进来。
   - 实测旧方案上沿取 848（真实 850）、下沿取 1278（真实 1269），多含 4 行人体/墙面 + 11 行腿部。
7. **边缘离散度必须实测为 0 才能交付**：从成片逐行取卡片左缘/右缘 x 坐标，统计 `max − min`。
   - 实测修复后左缘恒为 151、右缘恒为 568，离散度均为 0；
   - 修复前左缘在 148–151 之间逐行抖动（离散度 3 且带台阶），成片出现尖刺毛边。
   - 任何 > 0 的离散度都说明边界还在抖，禁止交付。
8. **交叉校验贴图层不含场景内容**：卡片内部与原视频第 0 帧的 `mean|diff|` 应极小（实测 0.0031），
   证明卡片内部是纯贴图、没有烤进人体或墙面。

### 4.5.1 自由造型插画（非矩形卡片）的边缘离散度口径

§4.5 第 7 条的「逐行左/右缘 x 的 max − min = 0」是针对**圆角矩形卡片**写的。
遇到**自由造型插画**（角色立绘、Logo 组合）时：

1. 「逐行左/右缘 x」的**绝对跨度天然很大**（角色轮廓本就不规则），该指标衡量的是造型复杂度，不是抖动；
2. 该指标真正要证明的是**该跨度在全片恒定** —— 即贴图没有逐帧跟踪/呼吸/宽度自适应。
   实测抽样 5 帧（k=0/60/120/200/244），左/右缘跨度逐帧完全相同 → 合格。
3. 交付时必须写清口径：「本片为自由造型插画，边缘坐标全片恒定（逐帧跨度一致），
   绝对值大是造型本身的不规则性」，不要报一个容易被误读成"抖"的裸数字。

### 4.6 复原上限（必须如实告知用户）

1. **烧录贴图无法 100% 逐像素复原**，必须如实告知用户，不得承诺"完全还原"。
   - **h264 压缩已经破坏原始亚像素 alpha 与噪声分布**：原视频里贴图边缘是 1 px 级软过渡 + 编码噪声，
     重建出的边缘必然与原始有差异（可能更干净、可能略有偏色）。
   - **原贴图是烤在视频2特定背景上的**：在"背景与 plate 同色"的位置，"原本透明"与"半透明叠在同色背景上"
     在像素层面不可区分，覆盖度不可逆。
2. 可以交付的是**更干净的重构**，不是逐像素复制：
   - 几何边缘（圆角矩形 SDF）比原始更规整；
   - 文字边缘用 proper matte 解算，可控在 1–2 px；
   - 代价是原始那种"软且抖"的边缘被抹平，观感更锐利、不像原视频。
3. 交付措辞必须区分：
   - ✅ "位置、尺寸、圆角、内容、时序与原视频一致，边缘做了几何化复原"；
   - ❌ "与原视频逐像素一致"（不成立）。
4. 若复原后与原帧存在残差，**必须在验证报告里量化**（例如框外残差 mean 与墙面 patch 对照，
   说明处于 x264 量化噪声级别），不能只写"基本一致"。
5. **可量化的验收基准（实测标定）**，可直接用作交付前的合格线：
   - **复原残差**：把提取出的 plate 回贴到原片自身的时间中值，残差应显著低于该区域的
     x264 量化噪声底。实测复原残差 0.11–0.13 灰度级 / 噪声底 1.39–1.63，比值 0.08 → 合格。
   - **字形保真度**：与原片同一帧、同一字形像素逐点比对，平均 |diff| 14–18 灰度级、
     >60 的差异像素 < 3% → 合格（超过 3% 说明 matte 或描边选取有缺陷）。
   - **颜色偏差**：字形核心的中位色应与原片基本一致（实测黄字 BGR 原始 (1,252,250) vs 复原 (9,253,245)）。
   - 以上三项任一不达标，先回头查：取色是不是用了均值、边缘是不是二值、描边是不是被 HSV 陷阱漏掉。

### 4.7 层的归属与互不污染（本次任务新增）

1. **静态图形层必须先分「归属」再抠 alpha。** 烧录层常常是"标题 + 插画 + 台标"三样东西叠在一起，
   它们的连通域在像素层面会互相粘连（插画压在标题上、台标压在插画上）。
   - 标题用**颜色签名**圈定：标题的填充是**高饱和**色（青/蓝渐变、纯黄），
     在标题带内用 `S ≥ 120 且 V ≥ 60` 圈出，再取「面积 ≥ 150 的全部连通域」
     （**不能只取最大连通域**——字形之间会断开，只取最大的那块会只捞到半个字）。
   - 描边用**几何环带**圈定：填充外扩 10 px 的环带内，按极性取描边色
     （极性由环带自身平均明度判定：亮=白描边，暗=黑描边）。
2. **标题的连通域不能漏进插画层。**
   用时序稳定判据得到"全部静态图形"后，必须再把**落在标题带内的连通域**从插画层剔除
   （判据：连通域外接框下沿在标题带内 → 归标题；插画那种贯穿到画面底部的组件下沿远在带外，不受影响）。
   实测漏判后果：插画层 bbox 从 `[117,1008,880,1840]` 污染成 `[42,1010,1055,1776]`，
   把整行标题糊进插画贴图，棋盘格预览里出现半截黄字。
3. **每个层都要独立出棋盘格预览**（1:1 原生像素）：插画层、标题填充 plate、标题描边 plate、
   动态数字逐帧 plate 各自一张，并额外出一张"全部 plate 叠回原片中值"的合成图。
4. **各层之间不得重复叠字**：填充 plate 与描边 plate 的 alpha 必须互斥（填充在描边内缘压住描边），
   不能让同一像素既算进填充又算进描边，否则字边被加粗。

## 五、黑色遮挡检测与贴图布局

### 5.1 遮挡检测

1. 在视频1前段逐帧检测近黑色、矩形/大连通域遮挡，同时用时间稳定性、轮廓和邻域判断排除自然黑色衣服、头发和裤子。
2. 计算每帧遮挡框 `(x0,y0,x1,y1)`，记录所有动作姿势下的边界，不要只看第一帧或中位帧。
3. 使用稳健统计得到主遮挡范围，并另行记录极端动作帧的外扩范围。不能把手臂、头发或背景误判成遮挡框。
4. **检测结果为空也必须报告，不得编造遮挡框**。生成式视频1 常见的真实烧录物不是黑色遮挡块，而是：① 只出现在最前面若干帧的贴图/文字残影（模型复刻了视频2 的贴图后随即丢失）；② 全片存在、位置固定但数值可能错误的倒计时数字（白字带深色描边）。
5. **先判断视频1 的倒计时数字与视频2 的是否同值同位，再决定处理方式——这是最容易做错的一步。** 生成式视频1 往往已复刻了视频2 的倒计时（同数字、同 x/y、同时间轴，误差 1–2 帧）。用描边叠合逐帧核对：
   - **同值同位（重合）→ 什么都不要做。** 既不要擦除，也不要把视频2 的数字叠上去：叠上去只会把字边加粗、把点糊在一起（本任务实测质心偏差最大 10.5 px，最差帧上「3..」会被糊成「3.9」）。
   - **不同值 → 才需要覆盖**，且**擦除必须先确认遮罩没有误含腰带扣/亮银饰件**。数字常常正好压在黑色腰带与金属扣上，对这类高对比硬边做 inpaint 会把腰扣抹成一团灰雾；实测 33 px 膨胀 + TELEA 在 176–250 帧区间留下整块"水面波纹"般的游动灰斑。宁可只擦字形本身（膨胀 ≤ 6 px）、宁可保留少量原阴影（视频2 数字自带阴影会盖住它），也不要把腰带一起 inpaint 掉。
6. 检测到空结果时，明确交付"视频1 无黑色遮挡块"的结论与依据（逐帧范围、排除规则），再按上面两类烧录物设计覆盖；不要因为提示词里写了"黑色遮挡"就默认它存在。

### 5.2 主贴图位置和尺寸

1. 保护区定义：
   - 遮挡框顶部以上的真实皮肤、胸部、锁骨、沟线；
   - 遮挡框左右之外的手臂、肩膀和身体轮廓；
   - 遮挡框底部以下正常可见的腹部、短裤、内裤或腿部。
2. 主贴图的上边界不得高于保护区边界。默认将主贴图向下放置，使原本可见的胸部/沟线保留；不得为了“完整覆盖”而把贴图整体上移。
3. 主贴图的下边界原则上不应超过黑色遮挡框底部，只允许 1–4 px 安全边缘；若视频2原始图片贴图本身确实覆盖下半身，则复用视频2原范围，否则裁掉图片下方多余内容。
4. 宽度用“用户红框意图 + 全帧覆盖安全性”共同决定：
   - 先按用户指定的视觉宽度建立窄版；
   - 检查所有帧黑块是否泄漏；
   - 若窄版无法覆盖极端动作帧，优先保持主贴图窄而稳定，不得把整个图片随帧拉宽；
   - 仅在黑块实际存在的像素上做极小范围辅助覆盖，并且必须使用源视频中的邻近服装像素或贴图像素，不能覆盖正常胸部、手臂或下半身；
   - 如果辅助覆盖会产生明显条纹、重复纹理、T 形、硬边或亮暗跳变，停止自动取舍，报告“窄度与无泄漏不可同时满足”，给出窄版和安全版两种结果。
5. 主贴图固定坐标。禁止：逐帧追踪、逐帧平移、逐帧缩放、宽度随黑块变化、用整块黑色补丁掩盖外扩区域。
6. 图片内部人物不要被横向拉伸；优先等比缩放并裁剪左右多余区域。贴图边缘保持干净、直线稳定，不能出现原背景条。

### 5.3 黑块外扩的处理边界

只有在以下条件同时满足时，才可使用辅助覆盖：

- 像素被检测为视频1烧录的近黑色遮挡，而不是自然衣服/头发；
- 该像素位于主贴图外侧；
- 辅助覆盖不进入胸部、脸部、手臂、短裤/内裤或腿部保护区；
- 辅助覆盖的来源是同一帧邻近真实黑色衣物，且边缘经过轻微羽化/颜色连续性检查；
- 放大预览没有出现条纹、重复贴图、假亮斑或明显不自然纹理。

无法满足时，不得“看起来差不多”地自动扩大贴图；应报告冲突。

## 六、合成与编码

1. 前段合成后，与视频2从帧 C 开始的后段拼接。后段原画面和原贴图行为不得改变。
2. 贴图合成必须使用统一色彩路径：所有分支显式设置 `bt709`、`tv` 范围、SAR=1；禁止让 FFmpeg 在未标记的 YUV/RGB 分支之间隐式转换矩阵。
3. 若使用 RGB 逐帧合成：输入、预览和输出验证都使用同一 RGB 解码/编码路径，并只在最终输出编码一次；若使用 YUV 直接混合，色度 Alpha 要按 2×2 降采样。
4. 音频直接复用视频2，尽量 `-c:a copy`；若封装要求重编码，必须说明原因并核对解码后音轨 MD5/时长。
5. 视频只编码一次最终成片；建议 `libx264`、`yuv420p`、高质量 CRF，并固定颜色参数。不要把中间预览版当最终交付。

## 七、全帧自动验证与交付

在交付前必须完成以下检查，不得只抽查 2–3 帧：

1. 帧数、FPS、分辨率、SAR、时长与视频2一致。
2. 换装切点 C 记录清楚；输出帧 `0..C-1` 来自视频1，`C..end` 来自视频2；边界帧单独查看。
3. 8 秒附近及所有动作关键点逐帧对齐，不能出现首尾姿势错位。
4. 黑色遮挡检测：所有被识别为遮挡的目标像素都被覆盖；若存在极少量自然黑衣误报，要区分并记录，不得用黑帧数量代替目标遮挡验证。
5. 保护区验证：贴图区外的胸部/脸部/手臂/下半身像素不应因合成被改变；对遮挡框上方和下方做逐帧 diff。
6. 贴图稳定性：主贴图坐标、宽高、边缘和文字坐标全片固定；不得产生抖动、漂移或宽度呼吸。
7. 文字 Alpha 检查：无孤立亮斑、粉色碎片、背景高光或重复文字；输出文字层预览和 2× 放大图。动态文字必须提供至少一个逐帧 Alpha 抽查。
   - **预览图必须 1:1 原生像素或 NEAREST 放大**：用 LANCZOS 缩放出来的预览本身就是模糊，会被误判成图层质量差
     （本任务曾把预览缩到 50%，误报"文字/插画不清晰"）。
   - **必须实测贴图边缘离散度**：逐行统计卡片左缘/右缘 x 坐标的 `max − min`，要求为 0（见 §4.5 第 7 条）。
8. **贴图语义污染检查：** 输出透明棋盘格贴图层，确认没有原视频人物、墙面、服装或完整截图；在前段全帧检查 Alpha=0 区域与无贴图版一致，重点检查约 3 秒和所有贴图切换点。
9. 全帧 rawvideo 平面 PSNR/零改动证明：贴图/遮挡保护区外尽量保持原始视频1像素；视频2后段与原视频保持一致。
10. 音频解码 MD5、时长和起始同步核对。
11. 交付主成片；如发现“窄贴图”和“黑块零泄漏”不可同时满足，额外交付窄版与安全版并说明差异，不得悄悄选择一种。

## 默认交付物

- `最终成片`：含贴图、文字、替换前段和原视频后段。
