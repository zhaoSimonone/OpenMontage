# 变装（Transform）视频精确分割

本 skill 沉淀自真实生产事故：切点错判 + 目视验证漏检，导致用户两次返工。所有规则
都是被验证过的教训，**按顺序执行，不得跳步**。

## 适用场景

- 用户要求把变装/cosplay/换装视频按"变装前、变装后"分割成 2 个视频
- 或任何"按画面状态把视频切成两段"的任务（前后状态由画面内容定义，而非给定时间点）
- 用户明确给出切点时间时，跳过第 2-4 步的"定位"，但仍必须执行第 5 步切割与第 6 步验证

## 核心教训（为什么必须这样做）

1. **目视批量看帧不可靠**：一次 Read 多张帧图时会混淆、漏判（真实事故：把红/粉造型
   内部的姿势切换误判为变装转场，错切 50 帧）。视觉判断只用于：参考帧确认、边界帧
   逐帧单独确认。全片分类必须程序化。
2. **缩略图拼贴图不能作为分类依据**：135×240 缩略图上相似色系造型无法区分。拼贴图
   只用于结构总览和交付给用户的核对材料。
3. **场景检测只能提候选，不能定切点**：同姿势换装跳切的 scene score 低于 0.12 检测
   不到；而同造型内的机位/姿势切换反而会触发高分。它两侧都可能是同一造型。
4. **`-ss` 单帧抽帧在某些文件上有偏差**（B 帧 DTS/PTS 偏移、edit list）：曾出现
   `-ss 7.7` 实际取到 8.3s 内容的事故。一切基于解码帧序号 `n`（select 滤镜）操作。
5. **`-t` 按 DTS 截止会多含 1 帧**：曾出现 `-t 8.28` 把 PTS 8.3 的帧包进输出。
   切割一律用 `select`/`trim` 滤镜按 PTS/帧号过滤后重编码，**禁止 `-c copy`**。
6. **简单颜色阈值会被皮肤/背景污染**：白衣造型里皮肤+暖色背景使红色调占比虚高。
   验证用"最近参考分类"（与 PRE/POST 均值直方图比距离），不用绝对阈值。
   **且直方图必须限定在躯干身体区域**（如高度 45%-85%、宽度 20%-80%），并加入
   亮度维度（亮像素占比区分白衣/黑衣、暗像素占比区分黑衣）：全帧直方图会被背景
   主导——真实事故：灰背景 + 低饱和双造型（黑裙 vs 白金cosplay）的全帧直方图几乎
   相同，分类完全失效；限定身体区域后 0 误分类。
   **低饱和双造型会让单一张量特征失效**（饱和度无法区分黑白与白金），必须多特征
   组合（色相直方图 + 亮/暗像素占比），且特征失效时立即切换为逐帧目视扫描。
7. **视频可能是穿插剪辑**：变装后画面里会切回变装前（同姿势跳切极隐蔽），
   甚至多次往返。必须先全片摸清结构，不能找到一个转场就切。
8. **分析帧与合成帧必须分离（成片禁用 JPG 中间帧）**：第 3 步分类抽帧用 JPG
   没问题（分析不需要无损），但分析帧**绝不能作为成片组装源**。真实事故：分析
   JPG 帧被直接复用来组装输出，整片多了一代有损压缩（vs 源直解 PSNR 掉到
   31dB、清晰度 −14%），用户验收"成片比原片模糊"。合成源必须满足以下之一：
   - **单趟 filter_complex（首选）**：select/trim/scale/concat/tpad 直接从源
     文件完成，全程无中间帧文件；
   - **无损 PNG 中间帧**：确需 Python 逐帧合成（定格/闪白/贴片）时，从源文件
     以 `-fps_mode passthrough` 抽 PNG，抽帧与组装共用这套 PNG。

## 执行流程

### 第 1 步：读元数据

```bash
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate -of json INPUT.mp4
```

记录：fps（按 `r_frame_rate` 算单帧时长，30fps → 0.0333s）、总帧数（约
`duration*fps`，最终以 select 解码计数为准）、有无音轨。

### 第 2 步：全帧拼贴图总览（判断结构，不做分类结论）

```bash
ffmpeg -y -v error -i INPUT.mp4 -vf "scale=135:240,tile=8x5:padding=2:color=white" /tmp/ck/big_%02d.png
```

逐张查看，回答一个问题：**这是单次变装、多次穿插，还是多造型（LOOK_A/B/C）？**
- 单次变装 → 后续找唯一切点
- 穿插剪辑 → 第 3 步必须找出**所有**切换点，切割时剔除穿插段后拼接（见"穿插结构切割"）
- 多造型 → 先建立 LOOK_A/B/C 分类并和用户确认哪些算"前"哪些算"后"，不得擅自二分类

### 第 3 步：程序化全帧特征分类（核心步骤）

提取全部帧为 jpg（文件名与帧号差 1：`f_0001.jpg` = 第 0 帧），计算每帧 HSV 直方图
+ 身体区（高度 42%-85% 带状区）饱和像素占比：

```python
# hue 12 bins (s>0.25, v>0.2), body_sat_frac, hair 区特征；逐帧与前一帧算 L1 距离
# 距离 spike 点 = 候选切换点；无 spike 的区间 = 同一造型
```

- 打印全时间轴的特征曲线，**所有** dist spike 都是候选切换点（阈值按实际数据调，
  真实换装通常 >1.0，姿势切换 <0.35，但必须目视核实每个候选，见第 4 步）
- 同一造型内部 dist 应全程平稳；若某区间内仍有多个候选点，说明可能是穿插剪辑

### 第 4 步：边界逐帧目视确认 + 稳定性规则

- 先看 2 个参考帧（如第 0 帧和片尾帧）锁定 PRE/POST 到底长什么样
- 对每个候选切换点，用**单帧单独 Read**（绝不批量）逐帧确认，标 PRE / POST / TRANSITION
  （运动模糊、遮挡、闪光、黑屏=TRANSITION）
- 应用规则：
  - `post_start_frame` = 第一个 POST 且**后续连续 ≥4 帧**仍为 POST 的帧
  - `pre_end_frame` = `post_start_frame - 1`
  - TRANSITION 帧不得当作 POST 起点；若切点两侧是 TRANSITION，归入前段（或按用户意图）
  - **过渡帧归属特例**：若 TRANSITION 帧画面已呈现 POST 造型（仅带模糊），该帧必须
    归入**变装后段**（作为其首帧），否则变装前片段末帧会闪现变装后造型，触发用户验收
    问题。归属原则：每一段内的每一帧的**画面造型**都必须与该段一致，过渡模糊不算例外
- 输出并复述：`pre_end_frame` 及 PTS、`post_start_frame` 及 PTS、判定依据
  （服装轮廓/领口/袖型/主色/发型/头饰变化）。不得依据脸部、字幕、贴图判断。

### 第 5 步：按帧号切割（重编码）

单切点（`post_start_frame = P`，音频切在 P 帧与前帧的中间时刻）：

```bash
MID=$(python3 -c "print((P-0.5)/FPS)")
ffmpeg -i INPUT.mp4 -vf "select='lt(n,P)',setpts=N/(30*TB)" \
  -af "atrim=end=${MID},asetpts=PTS-STARTPTS" \
  -c:v libx264 -crf 16 -preset slow -pix_fmt yuv420p -c:a aac -b:a 160k pre.mp4
ffmpeg -i INPUT.mp4 -vf "select='gte(n,P)',setpts=N/(30*TB)" \
  -af "atrim=start=${MID},asetpts=PTS-STARTPTS" \
  -c:v libx264 -crf 16 -preset slow -pix_fmt yuv420p -c:a aac -b:a 160k post.mp4
```

穿插结构切割（剔除 PRE 段中的 POST 穿插、POST 段中的 PRE 穿插后拼接）：

```bash
ffmpeg -i INPUT.mp4 -filter_complex "\
[0:v]select='(gte(n,A1)*lt(n,B1))+(gte(n,A2)*lt(n,B2))+gte(n,A3)',setpts=N/(30*TB)[v];\
[0:a]atrim=start=T1:end=T2,asetpts=PTS-STARTPTS[a1];\
[0:a]atrim=start=T3:end=T4,asetpts=PTS-STARTPTS[a2];\
[a1][a2]concat=n=2:v=0:a=1[a]" \
-map "[v]" -map "[a]" -c:v libx264 -crf 16 -preset slow -pix_fmt yuv420p -c:a aac -b:a 160k out.mp4
```

 HEVC 源一律转 H.264（`-pix_fmt yuv420p` 保证兼容），重编码保证帧级边界。

逐帧合成构建（定格填充/闪白/贴片等，输出帧无法用纯 select/trim 表达时）：
- **首选单趟 filter_complex**：freeze 用 `tpad=stop_mode=clone:stop=<秒>`，均匀
  变速用 `setpts`，简单叠白用 `framesync`/`blend`/`geq` 表达式——一条命令从源
  文件直出，无中间帧；
- filter_complex 表达不了的复杂合成才用 Python 组装，**组装源必须是从源文件
  直抽的无损 PNG**（见教训 8），禁止复用第 3 步的分析 JPG；
- 编码质量底线 `libx264 -crf 16 -preset slow`；定稿交付建议 crf 14。

### 第 6 步：100% 全帧验证（不许抽样）

1. **帧数对账**：两段 `nb_read_frames` 之和 == 源片总帧数，不等即丢帧/重复，必须重查
2. **最近参考分类**：从源片 PRE 区、POST 区各取 100 帧算均值直方图，对输出的
   **每一帧**计算与两个均值的距离，分到更近的一类；期望类与实际类不一致 = 违规，
   违规数必须为 0 才能交付
3. **边界帧目视**：前段末帧、后段首帧单独 Read 确认状态正确、动作衔接
4. **交付核对材料**：两段的全帧拼贴图 PNG 复制到输出目录
   （`变装前_全帧预览_126帧.png` 命名格式），用户可自查
5. **画质对账（防多代压缩）**：成片解码帧 vs 源直解 PNG 帧抽查 PSNR ≥ 40dB
   （尾段/后段应 ≥ 44dB）；不达标说明中间有多余压缩代，必须查管线重出
6. 用户质疑时先核对文件 mtime/md5——他可能看的是旧版或缓存；给新文件名副本排除缓存

## 检查清单（交付前逐项打勾）

- [ ] 全帧特征曲线看过，所有 dist spike 都已目视核实归属
- [ ] 结构判定完成：单次变装 / 穿插 / 多造型（多造型已和用户确认归类）
- [ ] post_start_frame 满足连续 ≥4 帧稳定 POST，TRANSITION 帧未计入
- [ ] 切割用 select/trim + 重编码，未用 -c copy、未用 -ss 单帧抽帧做依据
- [ ] 成片组装源为单趟 filter_complex 或无损 PNG；全链路无 JPG 中间帧（教训 8）
- [ ] 帧数对账相等
- [ ] 100% 最近参考分类 0 违规
- [ ] 成片 vs 源直解帧 PSNR 抽查 ≥ 40dB（无多余压缩代）
- [ ] 全帧拼贴图已交付到输出目录
